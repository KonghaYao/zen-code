# 模块文档模板

```markdown
# [模块名称]

> 路径：`[实际路径]`

## 概述

[1-3 句话描述模块职责]

## 文件结构
```

[模块名]/ ├── [文件].ts # [简要说明] └── [目录]/ # [简要说明]

```

---

## 文件：[filename.ts]

### 概述
[这个文件做什么]

### 关键导出

#### `functionName`
> 用途：[一句话]
- 重点：[需要注意的点]
- 重点：[需要注意的点]

#### `ClassName`
> 用途：[一句话]
- 重点：[需要注意的点]

#### `CONSTANT`
> 用途：[一句话]

### 依赖关系
- 依赖：[哪些模块/文件]
- 被依赖：[被哪些模块/文件使用]

---

## 注意要点

1. **[重要约束1]**：[说明]
2. **[重要约束2]**：[说明]
```

---

## 写作原则

### 1. 每个文件独立章节（严格执行）

- 每个重要文件对应一个 `## 文件：xxx` 章节
- **禁止**将多个文件合并到同一章节，即使它们功能相似
- 合并会导致检索时无法定位具体文件，破坏知识库的检索价值
- 唯一例外：只有**无任何导出的纯配置/类型文件**（如 `types.ts` 只有类型定义且小于 30 行）才可以附在相关文件章节末尾

### 2. 只标记重点

- 不写全部代码
- 只记录关键信息和注意事项
- 简短代码片段仅在必要时展示（核心用法、非显而易见的调用方式）

### 3. 简洁导出格式

```
#### `exportName`
> 用途：[一句话]
- 重点：xxx
- 重点：xxx
```

### 4. 标注依赖关系

- 依赖：哪些模块/文件
- 被依赖：被哪些模块/文件使用

### 5. 质量一致性

- 所有文件章节的详细程度应保持一致
- 核心文件（如入口、工厂、核心类）可补充代码示例
- 工具类文件可以简略，但不能省略"关键导出"和"依赖关系"
