# 如何使用 Interview 模式

> 1. `/interview` 或 `/i` 加上你的需求
> 2. AI 用 ask_user_questions 提问
> 3. 选择答案
> 4. AI 基于答案执行任务

## Interview 模式是什么

需求说不清楚的时候用这个模式。

比如你说"优化代码"，AI 不知道是优化性能还是可读性。你说"加个功能"，不知道加什么功能。

Interview 模式让 AI 提问你，用选择题的方式搞清楚你要什么。

## 使用流程

`/interview [需求]` → AI 用选择题提问 → 你选择答案 → AI 基于答案干活

## 怎么进入 Interview 模式

输入 `/interview` 或 `/i` 加上你的需求：

```
/interview 优化这个项目
```

或者简写：

```
/i 优化这个项目
```

## 接下来会发生什么

AI 不会直接干活，而是用 `ask_user_questions` 问你几个选择题。

比如上面这个例子，可能会问：

- 优化范围？单个组件 / 整个模块 / 整个项目
- 优化目标？性能 / 可读性 / 类型安全 / 测试覆盖率
- 时间限制？尽快 / 不着急

你用上下键选，按 `Enter` 确认。有些问题可以多选。

回答完所有问题后，AI 会总结你的需求，然后开始执行。

## Interview 模式适合什么场景

- 需求模糊（"优化代码"、"加功能"、"修问题"）
- 你不确定自己想要什么
- 任务涉及到关键文件（package.json、配置文件等）

## Interview 模式不适合什么场景

- 需求很清楚具体
- 简单直接的任务
- 只是问信息或查文档

## AI 问了太多问题怎么办

提示词里有限制，通常不会超过 5 个问题。如果问题太多，可以选择"自定义输入"，直接说你的想法。
