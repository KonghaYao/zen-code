# 如何使用 Plan 模式

> 1. `/plan` 加上你的需求
> 2. AI 用 ask_user_questions 提问
> 3. 回答问题
> 4. AI 生成计划（保存到 docs/plans/）
> 5. 选择立即执行 或 稍后执行
> 6. 引用 plan 文件让 AI 执行

## Plan 模式是什么

你有个功能要做，但不确定怎么下手。或者任务比较复杂，直接让 AI 写代码可能会走偏。

Plan 模式让 AI 先帮你规划，再动手。

具体来说：

1. AI 先问你几个问题，搞清楚你要什么
2. 读取相关文件，了解现有代码结构
3. 写一份详细的实施计划
4. 问你要不要立即执行

## 怎么进入 Plan 模式

输入 `/plan` 加上你的需求：

```
/plan 给用户个人中心添加头像上传功能
```

或者用简写 `/p`：

```
/p 重构支付模块，支持多种支付方式
```

## 接下来会发生什么

AI 收到你的需求后，不会马上写代码。它会：

### 第一步：提问

它会用 `ask_user_questions` 问你一些问题，比如：

- 头像支持哪些格式？JPG、PNG、GIF？
- 大小限制是多少？
- 要不要裁剪功能？
- 存到本地还是云存储？

这些问题是选择题，你直接选就行，不用打字。

### 第二步：收集上下文

AI 会去读相关的文件：

- 现有的用户模块代码
- 数据库结构
- API 设计模式
- 文件上传的现有实现（如果有的话）

### 第三步：生成计划

AI 会写一份详细的计划，保存在 `docs/plans/` 目录下，文件名是日期加功能名：

```
docs/plans/2025-01-15-avatar-upload.md
```

计划里每个任务都很小，大概 2-5 分钟能做完的那种。内容包括：

- 要改哪些文件
- 具体的代码片段
- 要运行的命令
- 怎么测试
- 边界情况处理

### 第四步：问你要不要执行

计划写完后，AI 会问：

> 计划已保存。现在执行吗？

你可以：

- 选"立即执行" - AI 开始按计划干活
- 选"稍后执行" - 计划存着，以后再说

## Plan 模式适合什么场景

- **新功能开发** - 需要改动多个文件
- **重构** - 影响范围大，需要先理清思路
- **复杂 bug 修复** - 不确定根因，需要排查步骤
- **技术调研** - 想让 AI 帮你分析方案

## Plan 模式不适合什么场景

- 简单的改动（改一个文案、修个小样式）
- 你已经知道怎么做，只是想让 AI 干活
- 紧急修复，没时间规划

## 计划存下来有什么用

即使你不立即执行，计划也存下来了。你可以：

- 自己看看，了解改动范围
- 分给别人做
- 过几天再让 AI 执行
- 作为文档留底

## 可以修改计划吗

可以。计划就是个 Markdown 文件，你可以直接编辑 `docs/plans/` 下的文件, 或者直接写给 AI, 让它进行改动。

改完后，把文件内容发给 AI：

```
按照 docs/plans/2025-01-15-avatar-upload.md 执行
```

AI 会读取你修改后的版本。
